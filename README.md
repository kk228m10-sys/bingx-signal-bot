# BingX Signal Bot

Telegram-бот, который после закрытия каждой 15-минутной свечи проверяет фьючерсы
BingX и присылает план сделки: направление, вход, стоп, три тейка, объём под
депозит и риск, примерную ликвидацию. Потом сам следит за сигналом и пишет,
когда взят тейк (и напоминает перенести стоп в безубыток) или сработал стоп.

**Бот ничего не покупает и не продаёт.** Он читает только публичные данные
BingX, ключ биржи ему не нужен. Сделки ставишь ты.

## Запуск

1. В `.env` — `BOT_TOKEN` (от @BotFather) и `ADMIN_ID` (твой Telegram ID).
   Образец — `.env.example`.
2. `python bot.py` или двойной клик по `start-console.bat`.
3. В Telegram: `/start`.

Нужен Python 3.10+, сторонних библиотек нет.

## Команды

| Команда | Что делает |
| --- | --- |
| `/now [монета]` | обзор: тренд по 1d/4h/1h, RSI, funding, OI, уровни |
| `/scan` | проверить сетапы прямо сейчас |
| `/open` | открытые сигналы |
| `/stats` | статистика всех сигналов в R и $ |
| `/watch`, `/add SOL`, `/remove SOL` | список монет (до 10) |
| `/balance 50`, `/risk 2`, `/leverage 20` | параметры расчёта объёма |
| `/pause`, `/resume` | выключить/включить новые сигналы |

Каждый день в 9:00 (по `TZ_OFFSET_HOURS`) — утренний обзор BTC.

## Автоторговля

Включается переменными окружения:

| Переменная | Значение |
| --- | --- |
| `TRADING_MODE` | `off` (по умолчанию), `demo` — демо-счёт BingX (VST), `live` — реальные деньги |
| `BINGX_API_KEY`, `BINGX_API_SECRET` | ключ BingX: чтение + торговля фьючерсами, **без вывода средств** |

Что делает бот на каждый сигнал: изолированная маржа, плечо не выше настроенного и
такое, чтобы ликвидация была дальше стопа, рыночный вход со стопом прямо в ордере,
три reduce-only тейка, после первого тейка стоп в безубыток. Если стоп не
подтвердился — позиция сразу закрывается.

Жёсткие ограничения: риск ≤ 2% от бюджета (`/balance`) на сделку, сделка
пропускается если минимальный лот даёт больший риск, до 2 позиций (по одной на
монету), дневной стоп 6% бюджета, при общей просадке 30% автоторговля выключается.
`/stop` закрывает сделки бота и выключает автоторговлю. Позиции, открытые вручную,
бот не трогает — но не торгуй вручную ту же монету в ту же сторону, пока у бота
открыта сделка по ней.

В демо автоторговля включена сразу, в `live` её нужно включить командой
`/autotrade on`. `/selftest` (только демо) проводит пробную сделку минимальным
лотом через весь путь: вход, стоп, тейки, закрытие.

## Монеты, варианты и обучение

- Сканируются BTC/ETH/SOL и топ-`/universe` альтов по объёму (по умолчанию 30, обновление раз в 6 ч).
- Варианты правил (`signals.VARIANTS`): `base` (проверенный), `retest`, `range` — каждый сетап
  каждого варианта сопровождается виртуально, его результат в R идёт в обучение (`learner.py`).
- Обучение: последние 40 результатов по группам (вариант, направление × тренд BTC, группа монет,
  монета). Группа с уверенно отрицательным результатом помечается. На демо это совет (бот всё равно
  входит и проверяет совет), на `live` — запрет, плюс торгуются только варианты с доказанным плюсом.
- Проверка на истории (`python backtest.py --alts 25 --days 60`, 60 дней до 2026-10-21): на альтах
  правила в минусе (−0.03…−0.13R на сделку), фильтр по BTC не помог; запрещающее обучение остановило
  почти всю торговлю, а оставшиеся сделки были не лучше — поэтому на демо оно только советует.

## Мини-приложение

`web.py` + `webapp/index.html`: обзор, сделки с причинами входа, обучение, журнал решений, правила.
Сервер слушает `PORT` (по умолчанию 3000); адрес задаётся `WEBAPP_URL` и ставится кнопкой меню бота.
Данные отдаются только по подписи Telegram initData владельца (`ADMIN_ID`).

## Как устроены сигналы

`signals.py`, параметры в `PARAMS`:

- **Отбой**: свеча-отбой (тень ≥ 40% диапазона) от сильного уровня — цены, где
  было несколько разворотов на 1h/4h.
- **Ретест**: пробой уровня на 1h с объёмом ≥ 1.5× среднего, затем возврат к
  уровню и удержание.
- Фильтры: тренд 1d+4h, RSI 1h, funding (перекос толпы), всплески волатильности.
- Стоп — за уровнем/тенью плюс запас в ATR. Тейки — чуть раньше следующих
  уровней. TP2 должен давать не меньше 1.5R после комиссий.
- Одна монета + направление — не чаще раза в 4 часа.

## Проверка на истории

```
python backtest.py BTC-USDT ETH-USDT SOL-USDT --days 30            # текущие правила
python backtest.py BTC-USDT ETH-USDT SOL-USDT --days 90 --grid     # подбор на 60д, проверка на последних 30д
python -m unittest discover -s tests                               # тесты расчётов
```

Бэктест считает вход по цене сигнала, комиссию тейкера, стоп первым при
неоднозначной свече, безубыток после TP1, закрытие через 72 часа.
Прошлый результат не гарантирует будущий.

## Файлы

- `bot.py` — Telegram, команды, расписание
- `signals.py` — сетапы, тейки, объём
- `tracker.py` — сопровождение сигналов и статистика
- `market.py` — данные BingX и индикаторы

- `data/state.json` — настройки, сигналы, статистика; `data/bot.log` — лог

## Telegram-каналы

`channel.py` читает веб-версию публичного канала (`t.me/s/<имя>`) и берёт из постов только тикер,
направление, цену, стоп и цели; посты с противоречивыми цифрами отбрасываются. Новые сетапы (не старше
2 ч) проверяются на BingX (монета есть, цена в пределах 5% от поста) и идут в бот как вариант
`tg:<имя>`: записываются для обучения, на демо исполняются с нашим риском. `eval_channel.py <имя>`
прогоняет историю канала на свечах BingX. Для @futures_club11 (55 дней до 2026-10-25): 73 закрытых
сетапа, 59% в плюс, в среднем +0.21R (вход по рынку после поста, стоп в безубыток после первой цели).
